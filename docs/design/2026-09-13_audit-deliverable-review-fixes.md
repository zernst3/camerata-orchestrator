## FIX 1 (MUST) — `Fix:` must be client remediation, never the detection recipe

Today `resolve_fix` (`report_export.rs:631-643`) binds the `Fix:` block to the
rule's default `[[option]].directive` — the **detection/enforcement recipe** (e.g.
"Regex-scan supabase/config.toml for `verify_jwt=false`… feed the matched source to
the prose tier…"). That leaks internals and confuses the buyer. Feeds PDF
(`report_export.rs:1080`), xlsx (`xlsx_export.rs:182`), findings.json (same
`FindingRow.fix`).

**Owner's approved hybrid — authored-per-rule, instantiated-per-finding:**

1. **New client-facing field.** Add `remediation` to `RuleOption` (`rules/src/lib.rs`
   ~399-413) + `OptionToml` (~380-390) + both build sites (~863, ~1180). Authored
   text = **2-4 imperative sentences: what to change, WHERE, and HOW TO VERIFY it's
   closed.** This is the SOLE source of truth; the Fix block binds ONLY to it.
2. **Placeholders, filled per-finding at render.** Remediation may use the SAME
   placeholder tokens the detection phrasing already uses (`<table>`,
   `<function-name>`, `<bucket>`, `<path>`, …), substituted from the finding at
   render time — so the guidance is identical across clients/reruns (retest-stable)
   yet names the specific object in THIS codebase. Fill from finding-carried values:
   `<path>`/`<file>` ← `Finding.path`; domain tokens (`<table>`, `<function-name>`,
   `<bucket>`) ← a structured capture map on the finding where the detector knows the
   object; **any unfilled token → a readable generic** ("the affected table", "the
   affected function"), NEVER a raw `<token>`. (Add `Finding.captures:
   BTreeMap<String,String>`, populated by the deterministic detectors that already
   match the object; enrich over time. Semantic/AI findings simply get the generic.)
3. **Optional per-finding line.** If the model-written `detail` carries a
   finding-specific remediation sentence, render it as a SINGLE labeled line UNDER
   the authored block: `For this finding: …`. Never in place of the authored block,
   never the sole content. (Guard against duplicating the body `detail` at
   `typ:133` — only surface a distinct remediation sentence, else omit.)
4. **No remediation authored → OMIT the Fix block entirely.** Never fall back to
   `directive` or any other rule field. Fail safe = silent, not leaky.
5. Apply the SAME binding to `findings.json.fix` and the xlsx Fix column (all three
   agree — keep the single-source design, just change the source).

Authoring: write `remediation` for the active/verified rule set (Supabase pack first
— it's what the sample + Mateo's copy use), then the rest. Omit-fallback covers any
not-yet-authored rule safely.
