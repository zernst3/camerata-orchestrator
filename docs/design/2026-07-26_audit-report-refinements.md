## The critique (as reviewed, verbatim)

# Camerata Audit PDF — Critique & Punch-List (2026-07-26)

Files: `sample-report/audit_report.typ` (template), `crates/server/src/report_export.rs` (serializer), `sample-report/data.json`, pages 1–10 PNGs, design doc §4.

Overall: the bones are genuinely good. The honesty framing (advisory footer on every page, "confirm against the live database," dirty-tree flag on the cover, what's-healthy section) is consistent and lands. The problems are (a) the sample PDF is materially *nicer than what the serializer can actually produce* — several sample strings are unreachable by the code, which means the flagship demo over-promises; (b) a handful of real logic/edge-case gaps; (c) page economy and emphasis inversion on the money page.

---

## MUST-FIX

**M1. "41 reviewed, 3 excluded as FP" leaves 31 findings unaccounted — the numbers don't reconcile.**
Sample: exec summary says "reviewed 41 candidate issues and surfaced 7"; methodology bold line says "41 reviewed; 3 dispositioned as false positives and excluded." 41 − 3 = 38, but the report body shows 6 code findings + 1 dep advisory. A skeptical technical buyer's first question is "where are the other 31?" In the serializer, `candidates_reviewed = report.findings.len()` and every non-FP finding appears in the report, so these numbers *cannot* diverge in real output — the sample data is fabricated inconsistently. Fix `data.json` (e.g. `candidates_reviewed: 10, excluded_false_positive: 3`) or, if a real pre-report drop stage exists (calibration discard), the methodology line must account for it explicitly. This is the single biggest credibility risk on the page, and it sits on the human-curation differentiator line.

**M2. Scorecard "Checked / clean" column is reversed.**
`audit_report.typ:97` header says `Checked / clean` but line 104 renders `clean_rules/audited_rules` → "4/7" reads as 4 checked, 7 clean. Swap values to `#str(row.audited_rules)/#str(row.clean_rules)` or relabel (`Rules clean / audited`). Also: the sample value itself is inconsistent — Supabase RLS has findings from 2 rules of 7 audited, so serializer logic yields 5/7 clean, not 4/7 (`data.json:30`).

**M3. A deterministic-floor critical can never reach the "Do now" cell.**
`report_export.rs:426–441` (`matrix_bucket`): Do now requires `effort == Some("low")`, but floor/preview findings never get calibrated effort (`None`) → every uncalibrated **critical** (hardcoded secret, service-role key) lands in "Do next." On the money page, the top-left cell can sit empty while the worst finding in the report sits in "Do next" — and `top_do_now` in the exec summary goes empty too (it draws only from `matrix.do_now`). The comment says the conservatism avoids downgrading; it actually downgrades urgency. Fix: for `Unresolved`, `severity == "critical"` → `do_now` regardless of effort; keep `high` + unknown-effort → `do_next`.

**M4. Serializer copy diverges from the (better) sample copy — real output will be visibly worse.**
- `methodology.not_done` (`report_export.rs:801–807`) has 3 bullets and is **missing the RLS migration-history caveat** ("dashboard changes never landed in a migration are invisible… confirm against production") that the sample renders on page 9. That is the strongest, most Supabase-specific honesty line in the report; add it.
- `AUDIT_REPORT_DISCLAIMER` (`report_export.rs:342`) is a shouty ALL-CAPS block; the sample page 10 shows the calm, board-appropriate paragraph from `data.json:234`. Ship the latter.
- `deterministic_note` / `ai_tier_note` / `severity_scale_note` in the serializer are terser and slightly *contradictory* (serializer claims floor is "always critical," yet the sample's floor category has zero findings and criticals come from the RLS replay). Port the `data.json:222–226` copy into the serializer constants when moving the template to `crates/server/templates/`.

**M5. `generated_at` will render as raw RFC3339 on the cover.**
`report_export.rs:780` emits `chrono::Utc::now().to_rfc3339()` → `2026-07-26T15:42:03.812345+00:00`. Sample shows `2026-07-26 15:42 UTC`. Format in the serializer: `Utc::now().format("%Y-%m-%d %H:%M UTC")`.

**M6. Empty-string options render blank cover fields.**
`ReportOptions` defaults all fields to `""`, but `or_dash` (`audit_report.typ:3`) only catches `none`. Export with no options modal input → cover has an *empty title line* and an empty "Prepared by" value. Fix `or_dash` to also treat `""` as dash (`if x == none or x == "" { … }`), and gate the project-title line like `client_name` already is. (Also `#set document(title: …)` becomes `" -- Camerata Audit Report"` with an empty title.)

**M7. Unresolved findings will say "Open", not "Do now"/"Do next"/"Plan" — the sample is unproducible.**
`disposition_label` (`report_export.rs:130–146`) returns `"Open"` for `Unresolved`, but every sample site shows its matrix bucket bolded ("**Do now**", "**Plan**"), which is far more useful. Align: emit `"Open — recommended: Do now"` (reuse `matrix_bucket`) or plain bucket labels. As-is, the real curated-findings section loses its per-finding call-to-action.

**M8. Long lines overflow the page edge (raw doesn't wrap in Typst).**
- Snippet blocks: `audit_report.typ:159` renders `raw(site.snippet)` in a block; a long minified/one-line snippet runs off the right edge.
- Inline raw paths: `raw(site.path)` (line 157) and the matrix cell `#it.path` — a deep `apps/web/node_modules/...`-style path can't break inside a word.
Fix in template: `#show raw: set text(size: 8.5pt)` plus wrapping (`#show raw.where(block: true): set par(justify: false)` + `set text(overflow …)`; simplest robust option is to break snippets into lines and truncate each to ~100 chars). AND in serializer: cap `snippet` at ~12 lines / ~800 chars with a `… (truncated)` marker — `Finding.snippet` is unbounded and one pathological finding currently gets unlimited page real estate.

## SHOULD

**S1. Page economy — 10 pages, ~4 mostly empty.** The unconditional `pagebreak()` after every section makes the matrix page ~2/3 blank, what's-healthy ~85% blank, dep snapshot ~90% blank, disclaimer ~90% blank. A board reader flips through and reads it as thin. Keep cover / exec / scorecard / matrix / findings on their own pages; merge What's-healthy + Dependency onto one page, and Methodology + Disclaimer onto one. (Counter-argument: one-section-per-page is defensible for print; but 3 near-empty pages in a row at the end is not.)

**S2. Emphasis inversion on severity.** Everywhere severity appears it's the *lightest* ink on the page (gray `#999`, parenthesized). On the money page the word "critical" is the least visible element in the cell. Give severity a colored chip (reuse the existing `chip()` — red critical, orange high, neutral medium/low) in matrix cells and finding site rows. Cheap, no assets, big legibility win.

**S3. Matrix and top_do_now omit the repo → ambiguous in multi-repo audits.** This very sample has the collision: `supabase/config.toml` exists conceptually in both repos; the matrix row for SUPABASE-AUTH-EDGE-JWT-1 doesn't say it's in `harbor-edge-functions`. `FindingRefJson` already carries `repo` — render it (`audit_report.typ:122`), and add repo to the serializer's `top_do_now` format string (`report_export.rs:726`).

**S4. Curated-finding heading orphans.** Page 5 ends with the SUPABASE-AUTH-EDGE-JWT-1 heading + site line; its snippet/detail land on page 6. Wrap the group heading + citation + first site in `block(breakable: false)` (or `show heading: set block(sticky: true)`-style keep-with-next).

**S5. Scorecard fallback categories are broken without a corpus.** `category_for` (`report_export.rs:406`) falls back to the first hyphen token lowercased: ALL `SUPABASE-*` rules collapse into one lowercase category `supabase`, floor rules become `sec`. The pretty categories in the sample ("Supabase RLS", "Secrets & keys") only exist via corpus `domain`. Since `corpus` is `Option` and best-effort, the degraded render is a real path: at minimum title-case the token; better, use the first two tokens (`SUPABASE-RLS` → "Supabase Rls" → title-case map).

**S6. What's-healthy will be much longer than the sample shows — decide the policy.** Serializer lists *every* audited rule with zero findings. Sample scorecard implies ~17 clean rules but the healthy page shows a curated 4. Real output on a big corpus = dozens of bullets, which reads as padding (inverse-FUD). Cap at the grounded-citation rules (kind == "grounded") + a summary line "N further rules verified clean this run," or cap at ~10. Also: when the list is empty the italic "Verified absent in THIS scan" tagline still prints under "No zero-finding rules to report" (`audit_report.typ:190`) — gate it.

**S7. Default narrative quality gap.** The engaging sample narrative is only reachable via hand-written override (and the sample even has `is_override: false` while showing hand-prose — fix the sample flag; as written the "Summary text supplied by the auditor" honesty tag would be *missing* on hand-written text). The real `default_narrative` (`report_export.rs:455`) is a dry count sentence, and `top_do_now` items are `RULE-ID — path:line` with no human title. Improvements: include the rule *title* in top_do_now ("Service-role key shipped to the browser — apps/web/.env.production:6 (SUPABASE-KEY-…)"), and special-case zero candidates ("The scan surfaced no candidate findings…" instead of "0 candidate finding(s) were reviewed; … 0 do now, 0 do next…").

**S8. Pluralization "(s)" everywhere.** "1 site(s)", "41 candidate finding(s)" — fine in a CLI, sloppy in a flagship board PDF. Do real pluralization in the serializer/template (both have the counts).

**S9. Coverage notes run together.** Page 8: both notes flow into one paragraph ("…ecosystems. Coverage note: Advisory data…"). Make each its own block/line (`audit_report.typ:216–218`).

**S10. Defensive severity casing.** Scorecard match (`report_export.rs:612`) buckets anything not exactly `"critical"|"high"|"medium"` into **low** — a `"Critical"` casing drift silently counts as low, and `matrix_bucket` likewise stops seeing it as high-severity. Normalize `severity.to_ascii_lowercase()` once at partition time.

**S11. `unreachable!` panic in server code.** `classify` (`report_export.rs:119`) panics if a FalsePositive slips through a future refactor of the partition loop. Make it `debug_assert!` + fall through to `Unresolved`, or return an Option. A PDF export should never be able to panic the server on triage data.

**S12. Dash usage (your standing rule).** The template copy uses em-dashes throughout (`---` in headings/site rows, `–` in the footer). Per your no-dash rule for user-facing copy produced under your name, decide whether client deliverables are in scope; if yes, swap for colons/commas in the prose strings (rule-id — title separators are arguably typographic, not prose, but the footer and narrative strings are prose).

**S13. Number formatting.** "486203 characters" on the cover → thousands separator ("486,203") or "~486k". Small, but it's the first page a board sees.

## NICE-TO-HAVE (flagged for scope)

- **Cover stat strip** (counts: 2 critical · 3 high · 1 medium · 1 accepted · deps 1 advisory). High value/effort ratio; the cover currently has ~60% dead space and the story doesn't start until page 2. *Mild scope-creep; I'd still do it.*
- **`#outline()` ToC + PDF bookmarks.** One line of Typst; clickable in every viewer. Cheap.
- **Scorecard row ordering** by status (Action-needed → Attention → Clean) instead of BTreeMap-alphabetical.
- **Effort/confidence as chips** (spec §4.5 says chips; current render is plain text). Cosmetic.
- **Missing-SHA copy**: "— (no git metadata) on unknown branch" reads clunky; collapse to "(no git metadata available)".
- **Empty `audited_refs`**: "Audited git state" heading renders with zero bullets — gate the heading.
- **Healthy-rule citation when corpus absent** labels every clean rule "(AI-advisory, model-inferred.)" — odd for a *healthy* list; suppress the label when kind != grounded.
- **Deep-tier "met" controls in what's-healthy** (spec §4.6 mentions; not implemented). *Defer — real scope.*
- **Per-repo grouping of curated findings** (spec says "grouped by rule within repo"; current is rule-only with repo labels on sites). Sites are labeled, so this is fine lean. *Defer.*
- **Matrix cell cap**: with hundreds of findings a cell becomes pages of bullets; cap at ~10 + "+N more (see Curated findings)". Only matters at scale — but it's the money page, so cheap insurance.

### Regression guard (required)

`report_export::tests::shipped_template_has_no_backtick_hash_interpolation_bug` asserts the
shipped template (`include_str!("../templates/audit_report.typ")`) never contains the literal
substring `` `# `` (a backtick immediately followed by `#`) — the exact pattern behind all
three original rendered-literal bugs (`` `#r.short_sha` ``, `` `#r.branch` ``,
`` `#site.path` ``). Confirmed the test fails against the pre-fix template and passes against
the fixed one.
